# QGIS Plugin Specification: `qskos` v2

## 1. Environment

| Item | Value |
|---|---|
| Target Platform | QGIS LTS 3.44 — Solothurn |
| Python | 3.x (bundled with QGIS) |
| Qt Bindings | PyQt5 |
| RDF Handling | `rdflib` (optional import — graceful degradation if absent) |
| CSV Handling | Standard `csv` module, UTF-8 |
| Geodata Storage | GeoPackage (`.gpkg`) via SQLite / OGR |
| Plugin Scaffold | Generated with **QGIS Plugin Builder** |

---

## 2. Purpose

**qskos** enables **semantic annotation of vector layer features** using concepts from SKOS vocabularies. Vocabularies and feature layers are both stored in and read from a user-selected **GeoPackage**, which is the single source of truth for the plugin. No reliance on QGIS project-file custom properties or layer metadata for persistence.

Core capabilities:

- Import SKOS vocabularies (Turtle, JSON-LD, CSV, URL) as attribute tables in a GeoPackage
- Track plugin configuration (vocab registration, feature–vocab bindings) in a dedicated `qskos_layer_config` table inside the GeoPackage
- Bind one or more vocabularies to a feature layer, with all bindings surviving project closure and GPKG moves (as long as the GPKG file is intact)
- Browse SKOS concept hierarchies and create typed annotation fields on feature layers, backed by `ValueRelation` widgets
- Generate hierarchical rule-based symbology from annotation values across all bound vocabularies

## 6. GeoPackage Data Model

### 6.1 `qskos_layer_config` table

Created automatically in the user-selected GPKG by `gpkg_manager.ensure_config_table()` on first use.

```sql
CREATE TABLE IF NOT EXISTS qskos_layer_config (
    layer_name  TEXT NOT NULL,   -- GPKG table name
    layer_role  TEXT NOT NULL,   -- 'ConceptScheme' or 'FeatureLayer'
    scheme_uri  TEXT NOT NULL,   -- vocab: own URI; feature layer: bound vocab URI
    language    TEXT,            -- vocab layers only; e.g. 'en', 'de'
    PRIMARY KEY (layer_name, scheme_uri)
);
```

**Rules:**
- A vocabulary layer has exactly one row: `layer_role='ConceptScheme'`, `layer_name=<table>`, `scheme_uri=<its own scheme URI>`.
- A feature layer has one row **per bound vocabulary**: `layer_role='FeatureLayer'`, `layer_name=<feature table>`, `scheme_uri=<bound vocab scheme URI>`. A feature layer with two bound vocabs has two rows.
- `language` is NULL for feature layer rows.

### 6.2 Vocabulary attribute tables

Each imported vocabulary is stored as a non-spatial OGR attribute table:

```sql
CREATE TABLE "<table_name>" (
    fid       INTEGER PRIMARY KEY AUTOINCREMENT,
    Concept   TEXT,    -- full concept URI
    prefLabel TEXT,    -- label in the import language
    definition TEXT,   -- definition in the import language
    broader   TEXT,    -- URI of broader concept, or empty string
    inScheme  TEXT     -- URI of the concept scheme
);
```

The table name is derived from the scheme URI's last path segment, sanitised to `[a-zA-Z0-9_]` (see `_safe_table_name()` in `gpkg_manager.py`).

Language is baked in at import time — only one language per table. The language is recorded in `qskos_layer_config.language`.

The table is also registered in `gpkg_contents` with `data_type='attributes'` so OGR/QGIS can discover it as a proper layer:

```sql
INSERT OR REPLACE INTO gpkg_contents
    (table_name, data_type, identifier, description, last_change)
VALUES (?, 'attributes', ?, '', datetime('now'));
```

### 6.3 Feature layers

Feature layers are ordinary spatial vector tables in the same GPKG (or any other data source). The plugin does **not** create feature layers — it annotates existing ones. Annotation fields added by the plugin are named after concept URIs (full URI string) and typed as `QVariant.Map` (stored as JSON arrays).

## 7. Plugin State

The main plugin class (`QskosPlugin` in `qskos_plugin.py`) holds all cross-tab state. Tab objects receive a reference to the plugin on construction and read/write state through it.

```python
class QskosPlugin:
    # Persisted per session (not across QGIS restarts unless saved to project)
    active_gpkg_path: str | None         # Path to the active GeoPackage
    selected_language: str               # Current import language ('en', 'de', ...)

    # Updated by tab interactions
    current_feature_layer: QgsVectorLayer | None
    current_vocab_layer: QgsVectorLayer | None    # vocab currently shown in tree
    current_vocab_scheme: str | None              # scheme_uri of current tree vocab

    # Performance cache
    hierarchy_cache: dict[str, tuple]    # layer.id() → (children_map, concept_labels)
```

`active_gpkg_path` is also saved/restored from the QGIS project file as a **project custom property** (`qskos:active_gpkg`). This is the only use of custom properties — it is a convenience shortcut, not the source of truth. The GPKG config table is always re-read on load.

## 8. Tab Specifications

### 8.1 Tab 1 — GeoPackage (new, mandatory first step)

**File:** `tabs/tab_geopackage.py`

**Purpose:** Select the GeoPackage that the rest of the plugin session operates against. Must be completed before the other tabs are functional.

**UI layout (QVBoxLayout):**

```
[ Select GeoPackage...  ]   [path/to/file.gpkg          ]
─────────────────────────────────────────────────────────
Vocabularies in this GeoPackage:
┌──────────────────────────────────────────────────────┐
│  conservationthesaurus  [en]  — https://...          │
│  materialthesaurus      [de]  — https://...          │
└──────────────────────────────────────────────────────┘
─────────────────────────────────────────────────────────
Status: ✅ GeoPackage selected. 2 vocabularies found.
```

**Behaviour:**

1. "Select GeoPackage…" opens `QFileDialog.getOpenFileName` filtered to `*.gpkg`.
2. On selection: store path in `plugin.active_gpkg_path`; call `gpkg_manager.ensure_config_table(path)`; refresh vocab list from `get_vocab_entries(path)`; emit a cross-tab refresh signal; save path to project custom property `qskos:active_gpkg`.
3. On project load: restore `active_gpkg_path` from `qskos:active_gpkg` if the file exists; auto-populate vocab list.
4. Other tabs check `plugin.active_gpkg_path is not None` before acting and display a "Please select a GeoPackage first" message if not set.
5. The vocab list (`QListWidget`) is read-only here — for import go to Tab 2.

---

### 8.2 Tab 2 — Vocabulary

**File:** `tabs/tab_vocabulary.py`

**Purpose:** Import a SKOS vocabulary from an external source (RDF/CSV) and store it as an attribute table in the active GeoPackage.

**UI layout:**

```
Source Type:      [ Local Turtle (.ttl) ▼           ]
Language:         [ en ▼ ]
Source:           [____________________________________]  [ Browse... ]

[ Load into GeoPackage ]

Status: Ready to import.
```

**Behaviour:**

1. Validate that `plugin.active_gpkg_path` is set; abort with message if not.
2. Validate source input is non-empty.
3. Call `skos_loader.load_skos_source(source, source_type, lang)` → list of concept dicts.
4. Call `extract_or_prompt_scheme_uri(concepts, source_hint)` → `scheme_uri`.
5. **Import guard**: call `gpkg_manager.scheme_exists_in_gpkg(gpkg_path, scheme_uri)`. If `True`, show `QMessageBox.question` asking for confirmation to replace. Abort on No.
6. Call `gpkg_manager.import_vocab_to_gpkg(concepts, scheme_uri, lang, gpkg_path)` → `table_name`.
7. Call `gpkg_manager.ensure_vocab_layer_loaded(gpkg_path, table_name)` to load the table into the QGIS project inside the `qskos [internal]` group.
8. Refresh the GeoPackage tab vocab list and Layer tab combo.

**Source type map:**

| UI Text | Internal key | rdflib format |
|---|---|---|
| Local Turtle (.ttl) | `ttl` | `turtle` |
| Local JSON-LD (.jsonld) | `jsonld` | `json-ld` |
| Local CSV (.csv) | `csv` | — |
| Remote URL (Turtle/JSON-LD) | `url` | auto-detect |

### 8.3 Tab 3 — Layer

**File:** `tabs/tab_layer.py`

**Purpose:** Select a feature layer from the active GPKG, manage vocab bindings for it, and create/browse annotation fields via the concept hierarchy tree.

**UI layout:**

```
Feature Layer:  [ buildings (GPKG)  ▼                     ]

─── Bound Vocabularies ───────────────────────────────────
┌──────────────────────────────────────────────────────┐
│ ● conservationthesaurus  —  https://...              │  ← selected
│   materialthesaurus      —  https://...              │
└──────────────────────────────────────────────────────┘
[ Bind Vocabulary ]          [ Unbind Selected ]

─── Concept Hierarchy (conservationthesaurus) ────────────
[ tree widget with checkboxes ]
```

**Feature layer combo:**
- Uses `QgsMapLayerComboBox` filtered to `VectorLayer | HasGeometry`.
- Exception list is populated by `refresh_layer_combos()` to exclude: (a) layers not from the active GPKG, (b) vocab tables (identified by `ROLE_VOCAB` rows in `qskos_layer_config`).
- On layer change: repopulate bound vocab list from `get_bound_vocab_schemes(gpkg_path, feature_table_name)`.

**Bound vocab list (`QListWidget`):**
- Each item stores `scheme_uri` in `Qt.UserRole`.
- Selecting an item calls `on_bound_vocab_selection_changed()` → loads that vocab's tree.
- The first item is auto-selected on feature layer change.

**Bind button:**
- Reads all vocab entries from config; removes already-bound ones.
- Shows `QInputDialog.getItem` with available vocabs.
- Calls `gpkg_manager.bind_feature_to_vocab(gpkg_path, feature_table, scheme_uri)`.
- Adds item to list; auto-selects it.

**Unbind button:**
- Shows `QMessageBox.question` confirming unbind; warns that annotation **columns are NOT deleted** and must be removed manually.
- Calls `gpkg_manager.unbind_feature_from_vocab(gpkg_path, feature_table, scheme_uri)`.
- Removes item from list; clears tree if the unbound vocab was selected.

**Tree view (`QTreeWidget`):**
- Built by `hierarchy.build_concept_tree_from_layer(vocab_layer)`.
- Checkboxes: checking a node → `create_annotation_field(concept_uri, label)`. **Unchecking does nothing.** No deletion dialogs.
- On load, existing fields on the feature layer are matched to concept URIs to restore checked state (`restore_checked_concepts()`).
- `itemChanged` signal is blocked during tree population to prevent spurious field creation.

### 8.4 Tab 4 — Symbology

**File:** `tabs/tab_symbology.py`

**Purpose:** Generate hierarchical rule-based symbology from annotation values across **all** vocabularies bound to the current feature layer.

**UI layout:**

```
Generate hierarchical rule-based symbology grouped by annotation
fields. All bound vocabularies are included automatically.

[ Generate Rules from Annotations ]
[ Reset to Default Symbology      ]

Status: Select a feature layer with annotation fields.
```

**Behaviour:**

1. Retrieve `current_feature_layer`.
2. Get all `bound_schemes` from config for this feature table.
3. For each bound scheme: `ensure_vocab_layer_loaded()` → `get_hierarchy_for_layer()`. Merge all `children_map` and `concept_labels` dicts into `combined_children_map` / `combined_concept_labels`.
4. Derive annotation fields: fields on the feature layer whose name appears as a key in `combined_concept_labels`.
5. For each annotation field (`field_uri`):
   - Collect directly annotated URIs across all features.
   - Walk ancestors of each annotated URI up to `field_uri` to collect intermediate concepts.
   - Build a group rule (filter: any descendant annotated), child rules (per visualised concept), and an else rule (unannotated).
6. Attach completed `QgsRuleBasedRenderer` to the layer and repaint.

The symbology logic is self-contained in `tab_symbology.py` and calls only `hierarchy.get_descendant_uris_fast()` and `core.field_utils.parse_field_value()`.

All SQLite access goes through this module. No tab or utility module touches `sqlite3` directly.

**Loading a GPKG layer (canonical pattern from PyQGIS cookbook §5.1):**
```python

# Add to project without showing in default layer panel position:

group.addLayer(layer)
group.setItemVisibilityChecked(False)
group.setExpanded(False)
```

## 10. Cross-Tab Signals and Refresh Pattern

Use a simple signal bus to avoid tight coupling between tabs. Add a `QObject` subclass as `plugin.signals`:

```python
from PyQt5.QtCore import QObject, pyqtSignal

class QskosSignals(QObject):
    gpkg_changed      = pyqtSignal(str)      # emitted with new gpkg_path
    vocab_imported    = pyqtSignal(str)      # emitted with scheme_uri
    binding_changed   = pyqtSignal()         # emitted after bind/unbind
    layer_changed     = pyqtSignal()         # emitted when feature layer changes
```

Each tab connects to the signals it cares about in its `__init__`. The GeoPackage tab emits `gpkg_changed`; Vocabulary tab connects to `gpkg_changed` to know when to enable the import form.

For layer combo refresh, use the existing safe pattern:

```python
QgsProject.instance().layerWasAdded.connect(self._schedule_refresh)
QgsProject.instance().layerWillBeRemoved.connect(self._schedule_refresh)

def _schedule_refresh(self):
    QTimer.singleShot(0, self._refresh_layer_combo)
```

## 11. `qskos [internal]` Layer Group

Vocab tables are loaded into a dedicated layer group that is kept collapsed and invisible. This is necessary because `ValueRelation` widgets require the referenced layer to be present in `QgsProject.instance()` — they look up layers by ID. A layer in a hidden/unchecked group still satisfies this requirement.

```python
root = QgsProject.instance().layerTreeRoot()
group = root.findGroup(INTERNAL_GROUP)
if group is None:
    group = root.insertGroup(0, INTERNAL_GROUP)
QgsProject.instance().addMapLayer(layer, False)  # addToLegend=False
group.addLayer(layer)
group.setItemVisibilityChecked(False)
group.setExpanded(False)
```

On project open, any previously loaded vocab layers will already be in the project (if the project was saved). `ensure_vocab_layer_loaded()` always checks for an existing layer before adding another, using `norm_path()` comparison on the OGR source string.
