# PATCH-README

Adds the new QSKOS RDF export (DCAT 3 + GeoSPARQL + Web Annotation, CIDOC CRM crosswalk in the ontology) to the LOD Export tab, together with the ontology, tests, a tool pipeline (diagrams as SVG/PNG, report, ontology documentation under `docs/`) and a `CHANGELOG.md` that explains every change. Intended for a branch, e.g. `rdf-export-v4`.

## Applying

Create the branch, then unzip at the repository root (every path is relative to it):

    git checkout -b rdf-export-v4
    unzip -o qskos-rdf-export-patch.zip -d .

On Windows without `unzip`: `tar -xf qskos-rdf-export-patch.zip` (works in current Windows 10/11) or extract with Explorer into the repository folder.

Two existing files are **overwritten**: `utils/lod.py` and `tabs/lod_export.py`. If your copy diverged from `master` (commit `9a6e0be`), merge by hand using `CHANGELOG.md` (section *Changed*). `PATCH-README.md` is not part of the repository; do not add it.

No deletions or renames.

## What to run

From the repository root:

    pip install -r tools/requirements.txt
    npm install -g @mermaid-js/mermaid-cli
    python tools/main.py

`python tools/main.py --list` shows the five steps (`example`, `test`, `diagrams`, `report`, `docs`). Without Node/mmdc the `diagrams` step still writes the `.mmd` files and warns; use `--skip diagrams` to leave the images untouched, or `--strict` to make the missing tool an error. On a machine where Chromium has to be pointed at explicitly: `set QSKOS_PUPPETEER_CONFIG=C:\path\puppeteer.json` (JSON with `executablePath` and `args`) and `set QSKOS_MMDC=C:\path\mmdc.cmd`.

It rewrites: `ontology/example.ttl`, `docs/*.md`, `docs/report.md`, `docs/diagrams/*`. No clock is read, so a second run changes nothing.

## How to verify

1. **Tests** — `python -m unittest discover -s tests -t .` → `Ran 29 tests … OK` (SHACL tests are skipped if `pyshacl` is missing).
2. **Rebuild is identical** — run `python tools/main.py` twice, then `git status --short`: the second run must not add changes beyond the first (the generated files appear once, as new).
3. **Everything listed, nothing else** — `git status --short` shows exactly the paths in the Contents table plus the generated files named under it.
4. **Example is current** — `python tools/main.py --only example` leaves `git diff --stat ontology/example.ttl` empty after the first commit.
5. **In QGIS (not checked here)** — open a project with an annotated GeoPackage, *LOD Export* tab: the new *Dataset metadata (DCAT)* box is visible; fill title, tick or untick the local-CRS box, export; the Turtle file starts with `@prefix as:` and contains `a qskos:Dataset`.
6. **In SPARQLing Unicorn (not checked here)** — load the exported file (or `ontology/example.ttl`) and the query `Q1` of `ontology/queries.rq` with `<LAYER>` replaced by the `qskos:FeatureLayer` IRI; the geometries should appear with the local CRS name taken from the end of the CRS IRI.
7. **Documentation** — open `docs/index.md` on GitHub (or enable Pages for branch/folder `/docs`): four pages plus report, diagrams visible.

## Verified here

Done in the sandbox against a fresh copy of the original (`leiza-rse/QSKOS`, commit `9a6e0be`) with this patch unzipped over it: `python tools/main.py --strict` (all five steps, tests 29/29 green including SHACL), run twice with byte-identical results (`cmp` on every generated file, diagrams included); regenerated files equal those of the working copy; `git status` lists the Contents paths plus the generated files and nothing more.

**Not verified here:** the plugin running in QGIS (no GUI/QGIS in the sandbox; the adapter is tested only against a stubbed `qgis.core` with fake layers, and `tabs/lod_export.py` only by syntax check), the import into SPARQLing Unicorn (its CRS-prefix handling is re-implemented in a test, not run), publishing on GitHub Pages, and Windows (commands are written for cmd; run in a Linux sandbox).
